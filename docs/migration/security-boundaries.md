# Rust-to-Node security boundaries

These boundaries are invariants for every migration wave. A Node implementation cannot become the default owner of a domain until its tests prove the relevant invariants.

| Boundary              | Current enforcement                                                                                              | Required Node invariant                                                                                                                                       | Evidence                                                                                                              |
| --------------------- | ---------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| IPC sender            | Electron accepts calls only from the trusted main frame and exact app/development URL.                           | No raw `ipcRenderer` or Electron event object is exposed; every invoke and subscription verifies the current frame.                                           | `electron/security.ts`, `electron/tests/boundary.test.ts`, `electron/tests/preload.test.ts`                           |
| Command validation    | Rust Serde validates nested inputs; Electron now also validates contract schema v1.                              | Schema validation occurs before resource acquisition or side effects. Unknown-field behavior stays compatible with the recorded Serde boundary.               | `electron/validation.ts`, `electron/tests/contract-schema.test.ts`, `native/tests/fixtures/tauri-argument-cases.json` |
| Host identity         | known_hosts verification precedes authentication, including both jump and target hosts.                          | Passwords, passphrases, keys, certificates, and agents are unavailable to the authentication step until the exact endpoint key passes policy.                 | `native/src/known_hosts.rs`, `native/src/connection.rs`, isolated SSH E2E                                             |
| Secret storage        | Credentials are held in platform stores; SQLite keeps metadata only.                                             | Existing service/account names remain readable. Secret values never enter SQLite, workspace files, diagnostics, or migration backups.                         | `native/src/keychain.rs`, `native/src/db.rs` migration tests                                                          |
| Secret redaction      | Reviewed execution and diagnostic paths redact known secrets.                                                    | Every command, tool result, provider error, and log record passes the same redaction boundary before persistence or emission.                                 | `native/src/execution/redaction.rs`, execution redaction E2E                                                          |
| Agent permission      | Rust owns permission modes, approvals, capability references, and effect classification.                         | Validation and approval happen immediately before execution; replay or recovery cannot reuse expired or mismatched authority.                                 | `native/src/agent_runtime/tool_pipeline.rs`, `native/src/agent_runtime/native_contract`                               |
| Filesystem scope      | Fixed-purpose commands validate paths and operation identity before work.                                        | Node handlers do not introduce arbitrary filesystem or SQL access through generic commands. Cancellation prevents new writes and progress after cancellation. | local/remote filesystem tests and command schemas                                                                     |
| Terminal containment  | PTY children are contained by Unix sessions or Windows Job Objects.                                              | Normal close, Core crash, Electron crash, and forced shutdown leave no descendant processes.                                                                  | `native/src/terminal_guard.rs`, terminal lease tests                                                                  |
| Terminal backpressure | Terminal traffic uses a dedicated bounded channel, strict sequence numbers, Renderer readiness, and ACK credits. | Node preserves ordering, UTF-8 incremental decoding, pause/resume, reload handling, and bounded memory.                                                       | `electron/native.ts`, `electron/terminal-flow.ts`, desktop protocol tests                                             |
| Data migration        | Startup uses a data guard, version marker, backup, and explicit offline recovery.                                | Node never modifies the only copy of unsupported or partially migrated data. Recovery requires explicit paths.                                                | `native/src/data_migration.rs`, `native/src/db.rs` migration tests                                                    |

## Release gate

A domain review must name its owned resources, applicable boundaries, failure modes, and automated evidence. “Feature works” is insufficient when cancellation, crash recovery, credential ordering, or persistence has not been exercised.
